# SC-03 — the mounted support controls the posed patient

Card `tsk_2d19693a11aed51e`, A-rows **A04** and **A05**. Machine evidence index:
[`sc-03.json`](./sc-03.json). This page explains the result; where the two disagree the JSON and
the command exit codes decide.

The card's claim is that a patient is placed on the support the case actually named, only once that
support is actually in the scene, using the offset the case actually authored — and that a slot
repair does not quietly discard any of it. Four production functions answered one of those
questions wrongly, and each is measured below on the unchanged tree.

## The four defects this card started from

Measured on `dc2ad3b8` before any product file was edited. None is an import error, an absent file
or a missing report: each is a shipped function returning a wrong answer to a question that ships.
Full transcript: `sc-03/red-baseline.txt` and `sc-03/two-sided-probe.txt` in the evidence store.

| # | function | input | reported | should have |
|---|---|---|---|---|
| 1 | `ensureActorPlacementsForStagedSlots` (`runtime-actor-placements.ts:108-118`) | a placement tagged with the wrong `slotKind`, carrying `headingRadians: -0.26` | the re-anchored record's `headingRadians` is `undefined` | carried the authored heading through the repair |
| 2 | `stageStationActors` (`actor-staging.ts:305`) | the SHIPPED ED manifest, which authors `headingRadians: -0.26` for the clinical slot | `nurse.rotation.y = -0.18`, framing's default; `openClinXrConsumedHeadingRadians` absent | applied the authored heading |
| 3 | `authoredPlantOffsetMeters` (`supported-actor-placement.ts:116`) | `scene_closure_supine_bedside_v1`, which authors `plantOffsetMeters {x: 0.12, y: 0, z: -0.08}` | `undefined` | returned the persisted offset |

Defects 1 and 2 are the same value lost at two different links, which is why the heading reached
nothing even on the one slot that read it. Defect 3 is structural: `authoredPlantOffsetMeters`
resolved through the module-level `scenarioBank`, and "authored case" and "in the in-repo fixture
bank" are opposites — so it returned `undefined` for precisely the encounters that authored an
offset, and a case whose offset was dropped looked identical to one that never authored any.

Defect 4 is the one the card names in as many words. `supportedActorPlacementPosition` has accepted
`supportInstanceId` and `mountedSupportInstanceIds` since the placement-provisionality card, and
its refusal to substitute a different instance of the same kind was written and tested. The live
caller never supplied either argument, so that refusal was unreachable, and the one refusal that
*was* reachable went to `console.warn` while the anchor was returned anyway.

## A kind is not an instance

The support id is `<environmentId>:<fixtureSlotId>` — `inpatient_ward_room_v1:stretcher`, not
`stretcher`. Every ward and every ED bay mounts a slot called `stretcher`
(`environment-zone-templates.ts`), so an unqualified id makes "the patient is on a bed" and "the
patient is on THE bed the case named" the same statement, and the substitution A04 forbids becomes
undetectable. The decoy in every control below is `ed_exam_bay_v1:stretcher`: same kind, different
instance, and a real one, because `main.ts` used to resolve every authored case's environment to
the ED bay through the same `scenarioBank` miss as defect 3.

The observation reads the scene by CONTACT SURFACE — `deckTopYMeters` for a bed, `seatHeightMeters`
for a chair, both written by the shipped builders — rather than by matching the slot name. A room
that renames its bed slot still mounts a deck; a layout prop that declares neither is not something
a body can rest on.

## The measurements

### Against SC-00's frozen rubric

`openclinxr.scene-closure-measurement-rubric.v1`. Only the thresholds this card's measurements
actually meet are claimed; the rest are named as not measured rather than left to look satisfied.

|---|---|---|---|
| authored offset visible on the posed patient (perceptual floor) | 0.005 m | x = 0.120000 m, z = 0.080000 m | 24x and 16x above the floor |
| unauthored control displacement (perceptual floor) | 0.005 m | 0.000000000 m | the whole allowance |
| authored vs unauthored patient separation (perceptual floor) | 0.005 m | 0.120000 m | 24x |

The perceptual floor is SC-00's, derived from `main.ts:2860`'s `PerspectiveCamera(52, 1, …)` at
3.4 m: three pixels on a 1920 px frame is 5.18 mm, rounded down to 5 mm. It is a property of the
display and no placement can move it.

**NOT MEASURED, and named so nobody reads a blank as a pass:** `support-contact`,
`support-penetration`, `floor-penetration`, `foot-slide`, `signed-floor-contact`, `limb-integrity`,
`swept-collision`, `arrival-error`, `settled-heading`, `stopped-observation`, `clip-motion-observed`,
`timestamp-monotonicity`, `sample-sufficiency`, `floor-frame-supported`. Those grade a RUN. This
card produces a placement, not a run; SC-05 and SC-07 own the run and the capture that feeds them.

### The heading defect is INSIDE SC-00's yaw tolerance, and that is the finding

The authored clinical heading is -0.26 rad and framing's default is -0.18 rad. The difference is
0.08 rad, **4.58 degrees**, against `settledYawErrorMaxDegrees` of 10. So a run in which the
authored heading was silently dropped would have passed SC-00's settled-heading metric with 5.4
degrees to spare.

The rubric is not wrong and is not widened. It grades whether a body ends up facing roughly where
it was asked to; it cannot grade whether the value it was asked for is the one a clinician chose.
Only a direct identity assertion catches this class, which is what clause (f) and (g) of the
behaviour test are. Recorded because the same shape will recur: a metric with a tolerance cannot
detect a decision replaced by a default that happens to sit inside it.

## The unauthored control is not a comparison against the default

SC-01 was rejected once for a control that filtered its expectation down to what the answer already
held. This one compares something that can differ, and did.

The treatment is `openclinxrSuppressAuthoredPlantOffset`, applied to the SAME station twice. The
body's own origin bias is identical in both passes and subtracts out exactly, so the delta between
the two skinned centres is the authored offset and nothing else — no fudge term, and no threshold
fitted to clear an observation.

- The **authored** ward case moves **0.120000 m** on x and **-0.080000 m** on z under that
  treatment, which is exactly what the case authors.
- The **unauthored** ED patient moves **0.000000000 m** under the identical treatment.
- The two patients sit **0.120000 m** apart, so "the control did not move" is a statement about a
  quantity that demonstrably can move, on the same axis, in the same units, in the same run.

If those two ever coincide the control has stopped measuring anything, and the behaviour test
asserts the separation directly for that reason.

## The behaviour test drives the shipped consumer

`apps/ui-xr/src/the-mounted-support-controls-the-posed-patient.test.ts` runs
`stageStationActors` over a real `three.js` scene carrying a real `buildStationEnvironment` shell,
with the real `applyCleanEncounterVisualReviewActorFraming`, the real
`supportedActorPlacementPosition` and the real `ensureActorPlacementsForStagedSlots`. The only
stub is the GLB fetch.

The posed body is the shipped patient GLB decoded from its own bytes — 10 skinned bodies, 45,475
vertex samples — composed through the slot transform and the loader's child-transform contract.
`three`'s `GLTFLoader` cannot parse those bytes in node: its texture path reaches `self`. The child
contract is therefore reproduced from `generated-loaders.ts:113-117` and the reproduction is
checked against that source in the test, so a change to the loader breaks the claim rather than
silently invalidating it.

No test in `apps/ui-xr` imports `main.ts` — it is a 4,822-line browser entry with module-level
`three.js` state. The live call site is asserted by a source read, the precedent set by
`the-composition-call-site-is-live.test.ts:20`, and its weakness is stated in the test: it proves
the call site passes those arguments, never that it runs. Every other clause is behavioural.

## What is not proved

**No transport to the acceptance owner.** The observation this card produces is shaped as SC-02's
`SceneRequirementObservation` and carries everything a scene consumer can honestly know — the
capability, the exact instance, the observed value, the outcome and the time. It carries no
`stationRunId`, `caseRevision` or `requirementRevision`, because those bind a record to a session
and are the session's to supply; a scene consumer that invented them would be a client authoring
its own admissible evidence, which `recordRequirementObservation` refuses at intake for exactly
that reason. **There is no route to send it.** `packages/openclinxr/rest` carries no
requirement-observation endpoint and `StationApiClient` no method, and both are outside this card's
frozen write roots. The runtime-side acceptance is complete and gates dependent motion locally;
binding it to a run at the API admission owner is unbuilt and is named here rather than left to be
discovered.

**No browser, no pixels.** Every measurement is offline geometry through the production consumers
in a node process on M1 Max. No dev server ran, no frame was rendered, no capture was taken.

**No clinical claim.** Whether 0.12 m along the deck is a clinically appropriate position for this
patient needs qualified review, which has not happened. These are engineering checks on geometry
and identity.

**No publication.** No Pages push, no deployment, no media.
