## How admission is decided

An observation must be able to speak for its requirement before its outcome is read at all. Binding
is checked first — source, run, capability, instance, requirement revision, case revision,
freshness — because a record from another run or a client can carry `outcome: "satisfied"`, and
reading the outcome first is exactly how a replayed acknowledgment admits an encounter.

The learner rule is separate and is the discriminator the contract asks for. A learner-owned
requirement is refused for sitting at its **goal** value, never for sitting at its authored initial
value: an observed `connected=false` satisfies the initial predicate and is recorded as a goal that
remains incomplete. Unknown and pending on a learner requirement refuse nothing, because neither
proves incompleteness or completeness.

## Scheduled effects

`advanceScheduledEvents` used to add every due event id to the emitted set and return, so "emitted"
meant "we told someone" and a consumer that threw lost its effect permanently. The emitted set is now
written only after the consumer returns an acknowledgment id. A failed effect stays unemitted and is
retried on the next tick with an incremented attempt; a duplicate tick at the same second applies
nothing; the domain clock is untouched by either. No effect may run before an accepted snapshot
exists, and an invalidated snapshot returns a stop signal instead of executing — the signal SC-05
consumes.
