Reference run

This page summarises reference run RR1: one emergency department (ED) chest pain case, compiled from its case blueprint into a synced multi-station practice circuit.

Chapter 1 — Doorway and Station 1 of 3

The learner enters and sees Station 1 of 3 from the server.

One server rotates the learner through the stations of a circuit, one station at a time, starting here.

The station comes from the case blueprint: actors, dialogue seeds, rubric labels and trace come from the scenario.

Chapter 2 — Spoken question and reply

The learner speaks; speech-to-text (STT) on the host transcribes the question, the actor answers with synthesized speech, and asks to repeat when confidence is low.

Actor speech is synthesized in the browser with text-to-speech (TTS).

Each turn is recorded with modality and confidence; replay captions are recomputed from the trace.

The capture will show learner and faculty panes side by side with the server clock; the learner pane shows Station 1 of 3 from the server and the faculty pane stays read-only; debug overlays hidden for capture.

Chapter 3 — Patient note

The patient note opens only in the note phase, is saved per station and replayed.

Notes are written as files on the host, alongside traces and faculty marks.

Chapter 4 — Station end, break, Station 2 of 3

A blueprint break pauses the rotation and shows a countdown.

After the break the learner pane reads Station 2 of 3.

Encounter flow buttons follow the server phase through the break.

Chapter 5 — Faculty lobby, replay, marks, lock

Faculty replay the station from its recorded trace.

Faculty enter rubric marks; a sign-off packet locks them.

The full run will live on the Release; trace link arrives with the capture.

Not exam-equivalent. No clinical validity. No validity is claimed for faculty marks or learner readiness. No Quest readiness claim. History-taking and communication only; no physical examination or touch is assessed. Formative practice and case authoring.
