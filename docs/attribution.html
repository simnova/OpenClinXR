Attribution · 2026-09-10

What we ship, who made it, and what is still unresolved.

Every third-party asset compiled into a shipped OpenClinXR humanoid or room is listed here. The authoritative record is the repository's third-party asset licence ledger, which carries the per-file evidence, the refusals, and the corrections. This page is the human-readable summary of the parts that actually ship, and it states the open questions rather than omitting them.

Shipping under a recorded assumption — disclosed, not resolved

Three components ship where the source page and the file header disagree about the licence. Each ships under a dated, named ruling recorded in the ledger rather than a silent decision, and each is listed here so the assumption is visible to anyone relying on this work. Two were ruled on by the repository operator on 2026-09-10; the third is still open.

If an upstream owner confirms that a copyleft header is the real grant, every asset derived from it will be re-baked without it and any published render carrying it will be withdrawn.

Recorded refusals

The ledger records assets that were acquired, measured, and then refused — among them Mixamo, whose terms forbid redistributing raw animation files, and CMU motion capture, which may not be resold even in converted form. Neither is a licence ambiguity: the restriction comes from someone other than the page's publisher, so no page statement overrides it.

When a page and a file disagree

MakeHuman assets frequently carry a pack page claiming CC0 while an individual file says something else. A ruling amended on 2026-09-10 settles which governs, in three shapes. Where the file is silent, the page's grant governs — an omission is not a contradiction. Where the file carries exporter template boilerplate a tool wrote rather than the author, the page governs. Where a specific file carries an explicit copyleft notice, the page does not govern by default: each such file needs a dated, named per-asset decision. Thirteen files are in that class today and none has one, so all thirteen remain refused.

The bake gate that decides what reaches a shipped file is deliberately stricter than this ruling and still refuses an absent licence line. An asset can be cleared by the ruling and still refused at bake time. That is intended: the ruling governs acquisition, the gate governs bytes a browser can fetch.

Corrections welcome. If you authored something listed here and the attribution or the licence reading is wrong, please open an issue on the repository and it will be corrected and re-baked.
