Measurement

What a mark is

A mark is a faculty-entered tick against one rubric label on a replayable station trace, locked by the sign-off packet. For assessment staff, including Objective Structured Clinical Examination (OSCE) directors: this page states what a mark is, what evidence exists now, and what is planned.

Rubric items are labels without definitions or anchors. Standardized patient (SP) case material — the opening line, history answers and authored affect — comes from the case document.

Counts with N

Turn counts are reported as counts with N: turns matched, turns unmatched and please-repeat turns from the reference run and the graded traces. The counts come from a single speaker, a single run and scripted utterances, not a rate.

Actor speech is synthesized in the browser with text-to-speech (TTS). Learner voice: synthetic (injected).

Deployment

Local-first means the synced circuit runs from one machine on the local network: the sync server, the speech-to-text (STT) sidecar and the trace, note and mark files live on that host; actor speech is synthesized in the browser; and the synced server and client carry no language-model dependency.

The data flow runs from the browser (learner interface and synthesized speech) to the LAN host (sync server, STT sidecar, trace, note and mark files). The diagram below is capture pending.

The browser needs HTTPS for microphone access (W3C secure-context requirement).

Traces, notes and marks are files on the host; there is no retention policy yet.

Integration status is ROADMAP: no LTI grade return, no single sign-on, no xAPI export, no validation study and no accreditation crosswalk yet.

Code is MIT; generated and third-party assets keep their own licences, listed in attribution.html and the licence ledger. Where an asset pack's index lists an open licence and the file carries none, the project follows the permissive listing by operator rule.
