# One worktree per lane; the shared main checkout is read-only

## Rule
- **Never edit tracked files in, or commit from, `/Volumes/files/src/openclinxr`** (the shared main checkout). Agents still start sessions there and read rules, skills and hooks from it.
- **Work in worktrees under `/Volumes/files/src/openclinxr-wt/<lane>-<topic>`.** Create each one from origin/main: `git -C /Volumes/files/src/openclinxr fetch origin && git -C /Volumes/files/src/openclinxr worktree add -b wt/<lane>-<topic> /Volumes/files/src/openclinxr-wt/<lane>-<topic> origin/main`, then `pnpm -C <wt> install --frozen-lockfile --prefer-offline`. Keep worktrees on `/Volumes/files` so pnpm copy-on-write clones work; `~/` is a different volume.
- Until the worktree root moves, dispatcher worktrees live under `OPENCLINXR_WT_ROOT` (default `~/.grok/worktrees/src-openclinxr`); the `/Volumes/files/src/openclinxr-wt` root is the target (card hx-paths makes the root resolvable).
- **Dispatcher resets also start from `origin/main`,** never from the local `main` HEAD.
- **Save daily WIP as commits on `wt/<lane>`** and push that branch to origin. No stashes. Land on `main` (`git push origin HEAD:main` from the worktree, as `push-queue.sh` already does) only when every hook passes. No `--no-verify` and no `OPENCLINXR_SKIP_HOOKS`.
- **Allowed in main:** gitignored runtime state under `.openclinxr/` (briefs, chain logs, handoffs, inbox, backups, locks). Tracked files stay forbidden.
- **One owner fast-forwards main.** Status: PROPOSED pending the operator's OK. Proposed owner: **Grok Bot (babysitter)**, with **loco** as backup. The owner may run only `git -C /Volumes/files/src/openclinxr merge --ff-only origin/main`, and only when main is clean. If the fast-forward fails, report it and stop. Never reset, restore, stash or checkout to make it pass. Grok Bot needs Patrick's one-time OK for this single write. It's the natural owner because it has no files of its own in main and already polls state.
- **Coordination files get a dedicated worktree, not an exemption.** `PROJECT_STATUS.md`, `operator-*.md` and the worker-backlog matrix are edited only in `/Volumes/files/src/openclinxr-wt/coord` (branch `wt/coord`). That worktree commits small, pushes through the hooks, and reaches main by fast-forward. *Why:* an exemption leaves uncommitted coordination edits in main. That's exactly what blocked loco's stash restore and skin's fast-forward this week (`PROJECT_STATUS.md` plus a 634-line registry edit), and an exempt dirty file blocks `--ff-only` forever. `orchestrator-only-main.md` needs to change its "CEO write roots" to mean "in the coord worktree".
- **Big binaries go to the asset store.** Put `.npz`/`.npy`/`.blend`/`.exr`/`.glb` files over 1 MB, and any file over 5 MB, in `/Volumes/files/openclinxr-assets/store/<lane>/<name>/`, alongside a `manifest.json` (`path`, `sha256`, `bytes`, `producer`, `source commit`). Reports cite store path + sha256. PNG evidence sheets of 3 MB or less may still be committed. A test that reads store assets must **fail**, not skip, when the asset is missing and the test runs in CI-equivalent mode.

## Commit-time large-file guard
Enforced by `tools/openclinxr/openclaw/large-file-guard.ts`, wired as the first step of the pre-commit and pre-push hook profiles in `agentic-hook-runner.ts`. Pre-commit scans the staged set (`git diff --cached --name-only -z --diff-filter=ACMR`, size from `git cat-file -s :<path>`); pre-push scans every blob in `origin/main..HEAD` (`git rev-list --objects` plus size) so a blob added then deleted inside the range is still refused. The reviewed allowlist `tools/openclinxr/openclaw/large-file-allowlist.json` is read from the base ref (`origin/main`), never from the working tree or index, so a commit cannot allowlist itself. There is no bypass flag: a violation fails the hook. Fix for binaries and over-limit files: move the file to the asset store with a `manifest.json` and cite path + sha256 in tracked JSON; fix for `.env*` and `.bak` files: remove them from the commit.

One-time operations (path fixes, hair rebuild, main-checkout migration) are tracked on the board, not here.
