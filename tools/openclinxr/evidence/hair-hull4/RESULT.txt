hull3.py owns the v4 inputs binding, so the fix (mirrored side views) is two
flags there: MIRROR_PROFILE (virtual camera R'=FRF across x=0 via
H.mirror_camera, mask=fliplr(profile), body depth rasterized from the same
station0b mesh) and MIRROR_3Q (chains hull2's own add_mirror_3q: explicit
mirrored camera + fliplr mask + rasterized depth). H.view_source already
routes 'profile_90_mirror' through the profile pipeline on x-mirrored points;
no carve rule changed. The dtype sizing rides along because the flags create
the first 6-view carve: base-3 state codes need 3**6=729 values > uint8, and
without it pack_states wraps silently (states max observed 728). 3-5-view
runs keep uint8 exactly as before.
